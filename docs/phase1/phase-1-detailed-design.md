# Phase 1 详细设计文档

## 目标

Phase 1 的目标是做出最小可玩的代际循环闭环：

村庄出发 -> 不可靠地图探索 -> 卡牌战斗 -> 旅行者死亡或结束 -> 生成前任回声 -> 下一任旅行者找到回声 -> 选择立刻吸收或带回村庄研究 -> 村庄长期状态改变。

本阶段只验证核心结构，不实现完整主线、完整牌桌技能树和二阶段。

## 体验边界

玩家需要明确感受到：

- 当前旅行者是会结束的个体。
- 村庄和牌桌会跨代保留部分成长。
- 前任回声是下一任旅行者的重要目标。
- 地图情报有价值但不完全可靠。
- 遗物选择会影响当前局和长期成长。

玩家暂时不需要体验：

- 复杂剧情分支。
- 真 Boss 与时间回溯。
- 多区域大地图。
- 大量卡牌和敌人内容。
- 重度村庄经营。

## 核心流程

### 1. 村庄准备

进入新局前，系统从村庄状态生成一任旅行者。

村庄提供：

- 当前训练等级。
- 已解锁卡池。
- 已知地图情报。
- 未找回的前任回声线索。
- 当前可用牌桌能力。

首版可以使用简化村庄界面或调试入口，但必须能表达村庄状态对新局的影响。

### 2. 新旅行者生成

新旅行者包含：

- 旅行者编号。
- 最大生命。
- 当前生命。
- 初始牌组。
- 当前遗物列表。
- 当前牌桌能力。
- 本局探索记录。

初始数值受村庄训练等级小幅影响。首版只需要一个最小成长例子，例如训练等级提高后最大生命增加。

### 3. 地图情报生成

地图展示的是情报，不是事实。

节点情报包含：

- 疑似节点类型。
- 风险等级。
- 收益等级。
- 可信度。
- 情报来源。

实际进入节点时，系统可根据可信度产生偏差。

首版推荐范围：

- 使用固定小地图模板。
- 每局随机 5-8 个节点。
- 节点类型包括普通战斗、事件、休息、前任回声、区域终点。
- 不准确优先体现在奖励和风险，其次少量节点误判，最后少量路线误差。

### 4. 节点探索

玩家选择一个可到达节点后，节点进入结算。

节点结果：

- 普通战斗：进入卡牌战斗。
- 事件：提供当前局或长期收益选择。
- 休息：恢复生命或调整牌组。
- 前任回声：进入遗物处理选择。
- 区域终点：完成本次最小探索或进入强战斗。

Phase 1 可以先用文本和按钮表达地图，不要求最终美术。

### 5. 战斗

战斗沿用现有能量制卡牌战斗。

当前已有系统：

- `CardData` 定义玩家卡牌。
- `EnemyData` 定义敌人和敌人行动。
- `StageData` 定义关卡敌人。
- `BattleConfig` 定义玩家数值、初始牌组和阶段。
- `BattleState` 保存战斗运行时状态。
- `DeckRuntime<T>` 管理抽牌堆、弃牌堆和手牌。
- `TurnController` 管理出牌、回合、敌人行动和阶段推进。

Phase 1 只需要接入探索流程和单场战斗结果，不要求重写战斗系统。

### 6. 死亡结算

旅行者死亡时，生成前任记录和前任回声。

前任记录包含：

- 旅行者编号。
- 死亡原因。
- 死亡区域或节点。
- 死亡时携带的关键卡牌、道具或牌桌状态。
- 本局确认过的地图信息。

前任回声包含：

- 来源旅行者编号。
- 关联区域主题。
- 线索文本。
- 可获得内容。
- 是否已找回。

### 7. 下一任找回回声

下一任旅行者开始时，村庄应显示或记录前任回声线索。

地图中可生成一个“疑似前任回声”节点。该节点不需要精确出现在死亡地点，但应与死亡区域主题或线索相关。

找到后提供两个选择：

- 立刻吸收。
- 带回村庄研究。

### 8. 立刻吸收

立刻吸收提供当前局收益。

首版可支持以下任意一种或多种：

- 获得一张前任卡牌。
- 获得一次性道具。
- 本局提高最大生命或恢复生命。
- 本局获得一个临时牌桌被动。

立刻吸收不提供或只提供很弱的长期收益。

### 9. 带回村庄研究

带回村庄研究提供长期收益。

首版可支持以下任意一种或多种：

- 解锁一张卡牌进入奖励池。
- 提高村庄训练等级。
- 提高某类地图情报可信度。
- 解锁一个牌桌能力的研究进度。

带回研究可以让当前局获得较小即时收益，但不能强于立刻吸收。

## 数据对象

### VillageState

村庄长期状态。

字段：

- `ActPhase`: 主线阶段，Phase 1 固定为第一阶段。
- `TrainingLevel`: 村庄训练等级。
- `UnlockedCardIds`: 已解锁卡牌标识。
- `MapIntelRecords`: 地图情报记录。
- `TravelerRecords`: 历代旅行者记录。
- `LegacyEchoes`: 未找回或已找回的前任回声。
- `TableProgress`: 牌桌成长进度。

### TravelerRun

当前单局旅行者状态。

字段：

- `TravelerId`
- `MaxHp`
- `CurrentHp`
- `DeckCardIds`
- `RelicIds`
- `ActiveTableAbilityIds`
- `VisitedNodeIds`
- `ConfirmedIntelIds`
- `FoundLegacyEchoIds`
- `IsDead`
- `DeathReason`
- `DeathRegionId`

### MapNodeIntel

地图节点情报。

字段：

- `NodeId`
- `RegionId`
- `DisplayedNodeType`
- `ActualNodeType`
- `RiskLevel`
- `RewardLevel`
- `Reliability`
- `IntelSource`
- `CanMisreadNodeType`
- `CanMisreadRoute`
- `CanMisreadRewardRisk`

### LegacyEcho

前任回声。

字段：

- `EchoId`
- `SourceTravelerId`
- `RegionHint`
- `Cause`
- `RewardPayload`
- `ImmediateClaimEffect`
- `ResearchEffect`
- `IsRecovered`

### TableProgress

牌桌成长进度。

字段：

- `UnderstandingStage`
- `UnlockedPassiveIds`
- `UnlockedActiveSkillIds`
- `ResonanceRules`
- `AwakeningTags`

Phase 1 只需要实现最小字段，不需要完整技能树。

## UI 需求

Phase 1 需要最小 UI：

- 村庄状态摘要。
- 新旅行者开始按钮。
- 地图节点列表或简化地图。
- 节点情报显示。
- 前任回声选择界面。
- 战斗界面复用现有原型。
- 死亡结算摘要。

不要求最终美术，不要求复杂动画。

## 验收流程

1. 启动游戏。
2. 从村庄开始第一任旅行者。
3. 选择地图节点。
4. 进入至少一场战斗。
5. 让旅行者死亡。
6. 查看死亡记录和前任回声。
7. 开始第二任旅行者。
8. 在地图中发现前任回声。
9. 选择立刻吸收，确认当前局收益生效。
10. 重复流程，选择带回村庄研究，确认长期成长生效。

## 不在本阶段决定的内容

- 最终存档介质。
- 最终 UI 视觉风格。
- 具体数值曲线。
- 全量卡牌、敌人、事件内容。
- 二阶段规则。
- 真 Boss 时间回溯战斗。
