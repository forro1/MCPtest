# Phase 1 测试与验收文档

## 目标

验证 Phase 1 的代际循环闭环是否成立。测试重点不是内容数量，而是核心状态能否在旅行者、地图、战斗、死亡、前任回声和村庄长期成长之间正确流转。

## 测试范围

包含：

- 村庄状态。
- 新旅行者生成。
- 地图情报。
- 探索节点。
- 战斗结果接入。
- 死亡结算。
- 前任回声生成。
- 前任回声处理。
- 长期成长。
- 最小 UI 流程。

不包含：

- 完整主线剧情。
- 真 Boss 时间回溯。
- 二阶段敌人规则。
- 完整牌桌技能树。
- 最终美术表现。

## 自动化测试

### VillageState

用例：

- 空村庄初始训练等级为 0。
- 添加旅行者记录后，记录数量增加。
- 添加前任回声后，回声数量增加。
- 研究回声后，村庄长期状态变化。

通过标准：

- 所有断言稳定通过。
- 测试不依赖场景对象。

### TravelerFactory

用例：

- 训练等级为 0 时生成基础旅行者。
- 训练等级提高后旅行者最大生命提高。
- 当前生命等于最大生命。
- 生成旅行者不会自动删除未找回回声。

通过标准：

- 旅行者生成可重复。
- 生成逻辑不依赖 UI。

### ExplorationMap

用例：

- 地图生成后节点数量在 5-8。
- 起点存在。
- 起点至少有一个可达节点。
- 节点显示类型和实际类型可以不同。
- 低可信度节点允许奖励风险误差。

通过标准：

- 固定随机种子下结果可重复。
- 不可靠情报有明确字段表达，不靠 UI 文本推断。

### LegacyEcho

用例：

- 死亡旅行者生成一个未找回回声。
- 回声包含来源旅行者编号。
- 回声包含区域线索。
- 立刻吸收后当前旅行者获得收益。
- 带回研究后村庄长期状态变化。
- 已处理回声不能重复处理。

通过标准：

- 两种处理路径都能独立验证。
- 回声状态变化明确。

### TableProgress

用例：

- 新牌桌处于沉默阶段。
- 解锁被动能力后可查询。
- 解锁主动技能后可查询。
- Phase 1 每局激活能力数量受限。

通过标准：

- 牌桌能力入口存在。
- 不要求完整技能树。

### BattleFlowAdapter

用例：

- 探索战斗节点能创建战斗请求。
- 战斗胜利返回胜利结果。
- 战斗失败返回失败结果和死亡原因。
- 失败结果能触发旅行者死亡结算。

通过标准：

- 不破坏现有 `CardBattleRuntimeTests`。
- 战斗结果能被 GameFlow 消费。

### GameFlowController

用例：

- 从空村庄开始第一任旅行者。
- 第一任旅行者死亡后生成旅行者记录。
- 第一任旅行者死亡后生成前任回声。
- 第二任旅行者可以开始。
- 第二任旅行者能发现前任回声。
- 处理前任回声后，当前局或村庄长期状态改变。

通过标准：

- 一次测试能覆盖两任旅行者核心循环。
- 状态变更不依赖手动操作。

## 手动验收流程

### 流程 A: 第一任旅行者死亡

步骤：

1. 启动游戏。
2. 在村庄界面查看训练等级和旅行者记录。
3. 点击开始新旅行者。
4. 进入地图界面。
5. 选择一个疑似战斗节点。
6. 完成或故意输掉战斗。
7. 进入死亡摘要。

预期：

- 死亡摘要显示死亡原因。
- 村庄旅行者记录增加。
- 生成一个前任回声。
- 村庄地图情报有更新。

### 流程 B: 第二任旅行者找回前任回声并立刻吸收

步骤：

1. 从村庄开始第二任旅行者。
2. 查看前任回声线索。
3. 在地图中进入疑似前任回声节点。
4. 找到回声。
5. 选择立刻吸收。

预期：

- 当前旅行者获得即时收益。
- 回声标记为已找回。
- 本次收益能在当前局界面看到。

### 流程 C: 第二任旅行者找回前任回声并带回研究

步骤：

1. 重新开始或使用另一条回声线索。
2. 找到前任回声。
3. 选择带回村庄研究。
4. 返回村庄。

预期：

- 当前局收益弱于立刻吸收。
- 村庄训练、卡池、地图情报或牌桌研究出现长期变化。
- 后续旅行者能看到该长期变化的效果。

### 流程 D: 地图情报不可靠

步骤：

1. 查看地图节点显示。
2. 选择一个低可信度节点。
3. 进入节点。

预期：

- 实际结果允许与显示情报有偏差。
- 偏差主要体现在风险和收益。
- 少量情况下节点类型或路线连接可出现偏差。
- UI 能让玩家理解这是情报不可靠，而不是系统错误。

## 回归测试

每次修改 Phase 1 系统后必须验证：

- 现有 `CardBattleRuntimeTests` 通过。
- 新增 Phase 1 Editor Tests 通过。
- 手动流程 A 和 B 至少通过一次。

## 失败记录要求

如果测试失败，需要记录：

- 失败时间。
- 失败用例。
- 复现步骤。
- 实际结果。
- 预期结果。
- 修复方式。
- 修复后验证结果。

记录位置为当前阶段开发日志或 Phase 1 文档的验收记录部分。

## 验收完成标准

Phase 1 只有在以下条件都满足时才算完成：

- 自动化测试覆盖村庄、旅行者、地图、回声、牌桌入口和主流程。
- 玩家能通过 UI 完成至少两任旅行者循环。
- 前任回声的立刻吸收和带回研究路径都可用。
- 村庄长期成长至少有一种可见效果。
- 地图情报存在不可靠性，并且玩家能理解这种不可靠。
- 现有卡牌战斗测试没有退化。
